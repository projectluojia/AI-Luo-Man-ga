# V3 智能体架构与校内落地推进会议纪要

## 一、会议目标

1. 明确 V3 智能体架构的核心设计与约束。
2. 确定项目在校内的场景切入方式和落地节奏。
3. 梳理校方可提供的资源及数据对接条件。
4. 明确校内数据调用的安全与合规要求。
5. 形成 Demo、场景调研、学生助理资料整理等近期行动方向。

## 二、讨论要点

### 1. V3 架构核心设计

#### 1.1 全链路运行逻辑

- 前端接入多端消息后生成唯一 `Echo ID`，用于绑定完整调用链。
- 消息由 Golang 中枢转发至 Python 开发的 Agent；Agent 完成多步调用后，结果沿原链路返回。
- 除统一数据库外，所有服务均采用无状态设计。各服务不得自建独立存储，所有需要持久化的数据统一写入数据库。
- 所有服务默认具备可调用属性。Agent 可直接向 Golang 中枢发起 Agent 调用请求，从架构层原生支持子 Agent 的全链路调用。

#### 1.2 架构约束

- **用户级鉴权：** Golang 中枢对每一次服务调用执行用户级权限校验，无权限请求直接拦截。
- **应用级隔离：** 通过 APP 命名空间实现跨应用权限隔离。
- **反小程序化：** 各服务不得自建用户体系、前端通道或独立数据库；未经授权不得私自触达外部平台；已有公共能力应优先复用。
- **规避 V2 问题：** V2 因服务独立存储、数据多副本冗余而造成代码逻辑不统一；V3 以统一数据库和无状态服务设计从根源上解决该问题。

#### 1.3 分层架构

- 在业务服务之下设置原子化“小工具层”，供多个服务直接复用公共能力。例如，通用课表查询能力无需为不同学院重复开发。
- 工具注册逻辑与服务保持一致，同时支持懒加载和内存自动卸载；长时间未使用的工具可自动释放内存。
- 通过宿主进程机制支持多语言组件：Golang 中枢按需拉起对应语言的宿主进程，由宿主进程承载公共组件。

#### 1.4 系统级包管理器思路

- 除将轻量小工具直接嵌入 Golang 主进程外，会议还提出了另一种实现思路：把底层小工具统一抽象为由系统级包管理器管理的组件。
- 包管理器从 Golang 进程中独立出来，负责底层工具的统一管理，降低工具实现与中枢进程之间的耦合。
- 该方案目前属于备选实现路径，需与工具嵌入 Golang 主进程的方案分别实现 Demo，再根据实际效果决定后续架构方向。

#### 1.5 服务加载分类

服务按资源占用和信任等级分为四种加载模式：

1. 嵌入式；
2. 宿主托管；
3. 独立进程；
4. 远程部署。

当前优先实现前三类核心能力。轻量工具可直接嵌入 Golang 主进程，以减少多进程调度开销；Agent 等高负载组件采用独立进程，以保障稳定性。

#### 1.6 调用风险防控

- 采用“调用链深度阈值 + 调用图实时校验”的双重机制。
- 对非幂等操作的循环调用直接拦截，避免无意义的资源消耗及重复执行风险。
- 各服务可在提交给 Golang 中枢的请求字段中自定义最大调用深度，以适配不同业务场景。

### 2. 项目落地路线

#### 2.1 落地原则

- 坚持需求牵引，拒绝脱离真实业务的纯技术导向开发。
- 架构迭代必须由实际场景验证，并优先完成必要的压力测试。
- 从校内低敏感业务切入，如校巴调度、公共服务查询、非涉密办事流程，再逐步扩展至更高权限场景。
- 先完成核心功能的小范围验证，在保障安全的前提下逐步扩大覆盖范围，避免一次性覆盖全量业务。

#### 2.2 校内现状与机会

- 当前“智慧珞珈”一网通办主要支持单轮对话引导，无法完成全流程办事闭环，用户仍需跳转至相应系统操作。
- 该缺口可作为智能体系统的重点验证方向，但需先通过调研明确真实痛点、业务流程及数据需求。
- 校方正在推进统一数据共享平台建设。后续可考虑将系统公共工具层接入该平台，实现跨系统能力复用。

#### 2.3 校方可提供的支持

- 非敏感数据接口可根据实际需求申请开放，具体范围须由校方统一评估并授权。
- 校方可提供算力、存储和真实业务场景支持。
- 可开放学生助理岗位，并提供相应劳务补助及官方项目认证背书。
- 支持团队先成立院级社团，成熟后再对接校级社团、中国计算机学会学生分会等资源。

#### 2.4 近期落地要求

- 尽快制作可直观展示系统核心能力的功能 Demo，并配套展示视频，便于对接方理解系统价值及适配场景。
- Demo 分别实现“轻量工具嵌入 Golang 主进程”和“独立系统级包管理器管理底层工具”两种方案，通过对比测试确定更合适的实现路径。
- 深度使用并调研“智慧珞珈”、一网通办等现有系统，梳理用户痛点、流程断点和可落地场景。
- 汇总学生助理定岗材料，为后续招募有热情的学生参与项目做好准备。

### 3. 合规与生态建设

#### 3.1 数据安全与授权

- 所有数据调用必须走官方授权路径，并严格遵守校内数据分级分类管理规则。
- 禁止通过逆向接口或其他非授权路径获取用户数据。
- 鉴于此前发生过非授权调用导致泄密的事件，数据接口申请、使用范围、调用日志和权限控制必须纳入项目设计。

#### 3.2 学生参与与生态孵化

- 学生参与项目应以不影响学业为前提，优先利用课余时间开展开发工作。
- 学生助理每周工作时长不得超过校方规定上限。
- 可通过院级社团起步，逐步争取更高层级的组织和行业资源支持。

### 4. 产品能力建议

- 强化用户记忆和用户画像能力，逐步实现基于使用习惯的主动服务推送，而不仅是被动响应查询。
- 结合一网通办等系统的真实使用流程，识别待建系统可解决的问题，并据此明确所需的数据范围和授权边界。
