# 协作材料脱敏与发布

本流程用于贡献证据、AI 协作记录、截图和申报材料的公开副本。它不替代校方数据授权，
也不要求删除主仓贡献者身份或改写 Git 历史。

## 原始证据与公开索引

原始 session history、截图、附件保存在仓外、限制访问的团队存储中。按实际工作需要授予
访问权限，不使用无需登录的分享链接。不要把原件提交到公共仓库、Issue、PR 评论或 CI artifact。
`.gitignore` 只帮助避免误提交，不能保护已经跟踪的文件，也不能阻止强制添加。

公开索引只记录以下最少信息：证据编号、贡献者、工作范围、相关 commit/PR、公开副本链接
以及该副本的 SHA-256。原件位置、原件摘要、访问人和保留/删除期限保留在受限台账中，
由证据编号关联；不要公开可直接访问原件的链接。保留作者归属和原始提交 SHA。

## 发布步骤

1. 从原件制作独立公开副本，删除凭据、Cookie、认证头、真实用户/校方数据、未获准公开的
   提示词和对话、私人联系方式、本机路径与内部服务地址。优先用贡献摘要替代完整会话。
2. 检查截图中的地址栏、终端、侧栏、弹窗和背景内容；使用实际移除像素的方式遮盖敏感区域，
   不只在可编辑文档中覆盖色块。删除图片元数据；检查 PDF/Office 的作者、批注、修订记录、
   隐藏页/工作表、嵌入附件和可复制文本。无法确认时只发布文字摘要。
3. 作者检查最终导出文件以及所有链接的目标和访问权限，计算公开副本摘要。在原有 PR 描述中
   写明证据编号、公开副本摘要和检查范围；原有 reviewer 在同一次评审中复核。没有额外审批层。
4. 原件不因制作副本而覆盖。若公开后发现泄露，立即撤销访问、轮换涉及凭据并按 SECURITY.md
   私下处置；删除当前文件不等于清除历史副本，不在公共评论中重贴泄露内容。

示例索引（仅为字段示例）：

| 证据编号 | 贡献者 | 工作范围 | commit/PR | 公开副本与 SHA-256 |
| --- | --- | --- | --- | --- |
| evidence-001 | 本人确认的账号 | 功能实现与验证 | 对应提交和 PR 链接 | 脱敏摘要文件、其真实摘要 |

## 自动检查与人工检查的边界

- GitHub secret scanning/push protection 识别其支持的凭据格式，不能识别所有个人信息。
- Core 与 Agent 的既有测试流程自动执行日志脱敏回归用例，覆盖普通消息、字符串、嵌套值、
  异常、格式化失败及 HTTP 日志；这些测试验证日志代码，不扫描任意附件或完整 Git 历史。
- 公开材料内容、截图像素、文档元数据及链接权限由作者和既有 reviewer 检查。当前没有 OCR、
  任意个人信息检测或 Office/PDF 自动清洗门禁。CI 通过不能代替本节发布检查。
- 双盲投稿需另按目标会议规则制作匿名副本；匿名化与秘密/隐私脱敏是不同的检查范围。
