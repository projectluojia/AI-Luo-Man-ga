# AI珞（爱珞）V3 包管理器设计

> 状态：设计稿
>
> 本文固定 AI珞 包管理器的完整契约。定位：**通用、多语言、可被其他系统直接使用的包管理器**（类似 npm 的产品形态）；AI珞 内核是它的第一个宿主消费者，不是唯一消费者。内容覆盖：包格式、无状态规范、版本设计、生命周期、宿主函数投影、**CI workflow 规范**、**多语言支撑**、**鉴权独立性**、工具链。配套 `v3_overall_design.md`（八）、`鉴权与委托授权设计.md`（六）、`仓库状态与路线图.md`（Loader 基线）。

## 一、目标与结论

1. **开箱即用**：包管理器是中立产品（包格式 + CLI + 注册表协议 + CI 规范 + **中立运行时**），复杂度只实现一次、随产品交付；其他系统通过客户端 SDK 接入中立运行时并注册自己的宿主能力适配器，**不重写装载机制**。
2. **多语言**：hosted = wasm32-wasi（任何可编译为 wasm 的语言）；isolated = 原生进程 + gRPC（`runtime_host.proto`，任意语言）；分语言 SDK 是主要投入。
3. **包无状态是硬契约**：包实例不持有权威业务状态；权威状态一律在宿主统一存储（AI珞 = Go L1，按 `app_id` 隔离）。实例可销毁重建、崩溃重启、升级迁移而无数据损失。
4. **版本化**：semver + 约束解析 + lock 固定；升级原子切换、旧版本 drain；降级只回滚代码、不回滚数据。
5. **鉴权只属于特定包**：只有涉及智慧珞珈数据/身份/委托 token 的包声明鉴权需求；其他包完全独立。鉴权由宿主（AI珞 内核）强制执行，**包管理器本身无鉴权语义**。
6. **CI workflow 规范**：npm 式发布流水线（构建 → 测试 → 版本 → 打包 → 发布 → 完整性/签名 → 安全扫描），以可复用 workflow 提供给包作者。
7. **安装 ≠ 授权**：包声明的权限只是上限，宿主 App 显式启用并授予后才生效（沿用鉴权设计六）。
8. **宿主函数永远在宿主**：安装包不能自带宿主函数实现；包在 manifest 声明所需宿主函数，宿主按声明投影并校验。
9. **bus 包化是第一个验收**：先统一内置/安装包契约，再把 `campus.bus` 真正放入安装目录。

## 二、现状基线

### 已实现（代码证据）

- 统一 Loader（`internal/kernel/loader`）：hosted（wazero 沙箱）/ isolated（进程）/ embedded 三种模式；capability / executor 两种角色；registered → loading → ready → unloading → failed 状态机；注册期按 Verify 绑定唯一宿主；Acquire/Release 在途引用；pin、idle TTL、单飞 Load、Warmup、RecoverFailed、Shutdown drain。
- 安装目录（`install_catalog.go`，`ailuo.install.v2`）：manifest.json + lock.json（manifest/artifact SHA-256）、严格 JSON、目录属主/权限/符号链接校验、工件 digest 重验、启动全量发现与原子注册（`RegisterInstalled`）。
- 内置 hosted 包：campus（go:embed wasm + 宿主函数 `ailuo.bus.query` + `bus.Store` 端口 + demo 播种）；参考安装包 `extensions/strings.tool`。
- main.go 已接线：`AILUO_RUNTIME_INSTALL_ROOT` 发现 + hosted backend + campus/agent 与 installed 记录同池注册。
- 跨语言线协议已定义：`runtime_host.proto`（Describe/Start/Health/Invoke/Stop，unary gRPC，任意语言可实现 Backend）。
- **阶段 1 地基（2026-08-22）**：semver 解析/比较/约束引擎（`semver.go`）；manifest 增加 `host_functions` 与 `storage` 声明并严格校验（`declarations.go`）；宿主函数按包投影——Verify 校验声明 ⊆ 宿主可用集合、Load 校验 guest 导入只属于声明集合（WASI 除外）；内置包与 installed 包统一 `validateRecordSpecs` 校验路径；campus 声明 `ailuo.bus.query` 宿主函数依赖与 `campus/bus` storage 契约（bus 包化步骤 1）。
- **分层重构（2026-08-22）**：中立包格式层 `internal/packmgr`（stdlib-only、可整体迁移独立 repo）：semver、声明、中性清单 `ailuo.package.v1`（核心字段 + AI珞 宿主扩展段 Extensions）、lock、进程规格与校验；Loader 保留运行时基座与 AI珞 宿主适配（Ext 严格解码为 registry 规格）。
- **阶段 2 核心（2026-08-22）**：Loader 原子升级流程 `Manager.Upgrade`——候选完成 Verify→Load→Describe→Start→Health 全绿后原子切换，新调用打到新版本，旧版本在途排空后恰好停止一次；候选失败不影响既有运行；Shutdown 有界等待退役版本停止。

### 缺口（设计要补齐的）

- **Loader 位于 `internal/`，无法被其他系统直接复用**：需抽取为公共运行时模块，AI珞 内核与中立运行时共用同一份实现。
- **中立运行时不存在**：没有随产品交付的 daemon/可嵌入运行时，也没有宿主能力适配器契约（storage/auth/宿主函数注册面）。
- **安装器/CLI/发布工具链不存在**：仓库没有生成 manifest/lock、写入安装目录或发布到注册表的工具。
- **依赖解析不存在**：semver 约束引擎与依赖声明已落地，但依赖闭包求解与 lock 生成（安装器）尚未实现。
- **CI workflow 规范不存在**：包作者没有标准构建/测试/发布流水线。
- **多语言 SDK 不存在**：wasm 信封与 gRPC 契约存在，但没有 per-language SDK 辅助开发。
- **注册表/签名未做**：只有本地目录 + SHA-256 锁定。
- **安装目录属主校验仅 Unix**：非 Unix 平台 fail closed（既有 P1）。

## 三、定位：中立基底与宿主

```text
包管理器（中立产品，开箱即用）
├─ 包格式：manifest + lock（语言无关的中性核心）
├─ CLI：init / build / test / publish / install / upgrade / uninstall / list
├─ 注册表协议：REST（npm 风格：发布 / 下载 / 版本索引 / 完整性）
├─ CI workflow 规范：可复用发布流水线
└─ 中立运行时（所有复杂度封装于此，一次实现）
   ├─ 装载、生命周期、沙箱（wazero）、版本解析、lock、drain
   ├─ 无权威状态：实例与 daemon 本身无状态，可复制、可重启
   └─ 宿主能力适配器契约：消费者注册自己的 storage/auth/宿主函数适配器

消费者（不重写装载机制，只接两个小面）
├─ 客户端 SDK：按 capability ID 调用（gRPC）
├─ 适配器注册：自己的存储/鉴权/身份/宿主函数钩子
├─ AI珞 内核（第一个消费者）：注册 ailuo.bus.query、智慧珞珈鉴权等适配器
└─ 未来其他系统：装 SDK + 适配器，开箱即用
```

- **包格式与宿主语义分离**：manifest 中性核心（id、version、language_runtime、abi、entrypoint、artifact、依赖约束、integrity）语言与宿主无关；Tool/Service/Capability、storage、host_functions、权限是 **AI珞 宿主扩展段**，其他宿主可忽略或自行解释。
- **命名保持中立**：工具与格式命名避免品牌绑定（`ailuo` 子命令可更名），不阻碍第三方采用。

## 四、包的定义与形态

### 4.1 安装目录形态

```text
<install-root>/<pkg-id>/          # 目录名 = 稳定包 ID
├─ manifest.json                  # 清单（中性核心 + 宿主扩展段）
├─ lock.json                      # 解析锁定：版本 + SHA-256 + 进程规格
└─ artifact/                      # 工件（wasm / 可执行文件 / 多文件）
```

### 4.2 角色

| 角色 | 行为 | 现状 |
|---|---|---|
| `capability`（宿主扩展） | 能力提供者：经宿主 Dispatcher 被调用 | strings.tool（tool-only）、campus（service 包） |
| `executor`（宿主扩展） | 驱动 Agent Run 会话 | 内置 agent |
| 无角色（中性） | 纯工件/库包，无宿主语义 | 预留 |

### 4.3 manifest 分层

```jsonc
{
  // —— 中性核心（语言/宿主无关）——
  "id": "campus.bus",
  "version": "1.0.0",
  "language_runtime": "wasm32-wasi",        // 或 native + gRPC
  "entrypoint": "artifact/campus.wasm",
  "artifacts": [{"path": "...", "sha256": "..."}],
  "dependencies": [{"tool_id": "bus.query", "constraint": "^1.0.0"}],

  // —— AI珞 宿主扩展段（其他宿主可忽略）——
  "tools": [], "service": {}, "capabilities": [],
  "storage": {"namespace": "campus/bus", "schema_version": 1,
              "migrations": [...], "sensitivity": "public", "retention": "permanent"},
  "host_functions": [{"module": "ailuo.bus", "name": "query", "purpose": "authoritative store query"}],
  "permissions": ["campus.bus.read"]
}
```

规则：storage / host_functions / permissions 是**声明**，不是执行凭据；缺省字段保持现有行为。

## 五、无状态规范（核心原则）

1. **实例无权威状态**：包实例（Runtime）不保存跨调用权威状态；内存缓存可随时丢弃；实例重启、重建、迁移、升级不丢数据。权威状态一律经 storage 声明落宿主存储（AI珞 按 `app_id` 隔离）。
2. **凭据不落入包**：包不持有数据库凭据、第三方 token、秘密；需要外部能力时经宿主函数投影（受信计算基）。
3. **崩溃语义**：实例崩溃 → 宿主标 `failed` → `RecoverFailed` 重建新实例；在途调用有界失败，已持久化状态不受影响。
4. **幂等与重放**：写类 Tool 必须声明幂等键语义，重放安全（沿用 `internal/kernel/idempotency`）。
5. **存储访问**：业务数据经声明的 storage 端口/宿主函数读写；App 隔离在宿主侧强制（guest 无法伪造 `app_id`）。
6. **禁止项（Verify 与审计拒绝）**：包内自建私有库、包持有第三方凭据、包把用户状态留在进程内、包私建子任务。

验证：实例重启/升级后状态一致测试；崩溃恢复测试；跨 App 隔离测试。

## 六、版本设计

### 6.1 版本号：semver 2.0

- `MAJOR.MINOR.PATCH`（可选 `-pre` / `+build`）。包内全部规格与 runtime 同版本（现有校验已强制）。
- 版本号是包的**公共契约**：对宿主、App 配置、lock、审计均可见。

### 6.2 兼容性语义

| 变更 | 示例 | 行为 | 治理 |
|---|---|---|---|
| patch | 1.0.0 → 1.0.1 | 仅修复；schema、语义、权限不变 | 热替换；无需宿主确认 |
| minor | 1.0.0 → 1.1.0 | 向后兼容新增：新 Tool/Capability、可选参数 | 现有契约不变；**新 Capability 默认不进任何 App**，需宿主控制面显式启用 |
| major | 1.x → 2.0.0 | 破坏性：schema、语义、权限、存储 schema 变更 | 宿主控制面显式确认（generation CAS）；可能伴随存储迁移 |

### 6.3 版本约束与解析

- 约束语法：精确 `1.2.3`；caret `^1.2.0`（≥1.2.0 且 <2.0.0）；范围 `>=1.0.0,<2.0.0`。
- 解析时机：安装/升级时按依赖闭包求解 → 写入 lock（固定版本 + SHA-256）。
- **版本唯一性**：同一宿主内同一 `tool_id` / `capability_id` 只允许一个已发布版本；升级是版本替换，不做多版本并行（避免路由歧义；有明确需求再放宽）。
- 冲突：依赖闭包不可满足 → fail closed，须显式调整约束。

### 6.4 升级与降级

- **minor/patch 升级**：candidate 完成 Verify → Load → Describe → Start → Health 全绿后原子切换（新版本接新调用），旧版本 drain（`in_flight` 归零）后有界停止；宿主配置与 Run 状态不受影响。
- **major 升级**：宿主控制面显式确认；存储迁移前向执行成功后激活；失败保留旧版本可回滚（代码回滚，**数据不回滚**）。
- **降级**：仅工件/代码回滚到 lock 上一版本；存储 schema 只前向，不自动回滚数据。
- **升级不扩权**：新增 permissions 不自动进入既有 App（鉴权设计 6.2）。
- 升级全程幂等；失败保留旧句柄供 Shutdown 清理。

## 七、多语言支撑

| 运行模式 | 语言 | ABI | 现状 |
|---|---|---|---|
| hosted | 可编译 wasm32-wasi：Rust、Go(tinygo)、C、AssemblyScript 等 | stdin/stdout JSON 信封 + 宿主函数 import | wazero 沙箱已实现；`extensions/strings.tool` 为参考 |
| isolated | 任意语言（Python/Go/Rust/...） | `runtime_host.proto` gRPC unary | 协议、监管、进程规格已实现 |
| embedded | 宿主内嵌语言（Go） | 进程内函数 | 机制已有，无生产包 |

- **per-language SDK（新增，主要投入）**：`ailuo-sdk-go` / `ailuo-sdk-rust` / `ailuo-sdk-python` 等，提供信封编解码、宿主函数调用约定、schema 助手、生命周期（Describe/Start/Health/Invoke/Stop）骨架；SDK 与 CLI 共享同一契约定义，避免各语言漂移。
- **能力差异**：wasm 无文件系统/网络（WASI 裁剪）→ 需要内核能力必须走宿主函数；isolated 进程可自行访问网络，但凭据仍经宿主投影（fail closed）。
- 契约中立性：SDK、信封、gRPC 定义均不引用 AI珞 业务语义，其他宿主可复用。

## 八、宿主函数投影（host function）

- 宿主维护**宿主函数注册表**：`module.name → 实现`（AI珞 内核 Go 代码，受信计算基）。当前第一个实例是 `ailuo.bus.query`。
- 包 manifest 声明所需宿主函数；**Verify 时**校验注册表包含；**Load 时**只投影声明集合（wasm 侧只 import 声明的 module/name，未声明调用直接拒绝）。
- 内置包与安装包共用同一注册表与投影校验。
- 通用宿主函数能力面（`storage.*`、`observe.*`、`identity.*` 等）作为逐步投影候选，每个都有闭式协议、App 隔离强制与泄露负向测试。
- **中立性**：宿主函数是 AI珞 宿主能力，不是包格式的一部分；不依赖它们的包（无 host_functions 声明）可在任何宿主/独立环境运行。

## 九、CI workflow 规范（npm 式发布流水线）

包作者仓库的标准发布流水线，以**可复用 workflow**（GitHub Actions `ailuo-package-publish` 等）形式提供，各包仓库 `uses:` 即得：

| 阶段 | 内容 | 产出/校验 |
|---|---|---|
| 构建 | 按 `language_runtime` 构建（wasm 交叉编译 / 原生构建）；固定工具链版本保证可复现 | 可复现工件 |
| 测试 | 单元测试 + 对宿主 substrate 的集成测试（wasm 信封 golden、gRPC 契约） | 测试证据 |
| 版本 | semver 由 conventional commits 或显式 tag 决定；校验 `manifest.version` 与 git tag 一致 | 版本一致 |
| 打包 | 生成 manifest + lock + artifacts + integrity（SHA-256）；lock 固定解析闭包 | 完整安装目录 |
| 发布 | 推送注册表（注册表鉴权只认证包作者，**与智慧珞珈无关**）；SLSA provenance；签名（预留） | 不可变版本 |
| 安全 | 依赖漏洞扫描、secret 扫描、工件哈希复核 | 通过门禁 |

- **不可变版本**（npm 式）：注册表已发布版本不可覆盖；错误版本通过新版本修复。
- 发布是受信操作（CI 角色/控制面），与运行期调用鉴权无关。
- 门禁：包作者 PR 必须通过 CI 才能发布；发布事件全审计（包 ID、版本、发布者、结果）。

## 十、鉴权独立性

### 10.1 两个鉴权面（均服务端统一）

| 鉴权面 | 作用 | 归属 |
|---|---|---|
| 注册表鉴权 | 包发布者/下载者身份认证（npm 式），与智慧珞珈无关 | 注册表服务端统一处理 |
| 运行时鉴权 | 每次调用的身份解析 + 授权校验 | 经宿主能力适配器契约在服务端统一执行；AI珞 三层鉴权是参考实现，其他系统通过同一适配器接口接入自己的策略引擎 |

- 接口统一、策略归消费者：适配器契约（身份解析、授权检查、审计回调）由中立运行时定义；AI珞 的 `鉴权与委托授权设计.md` 三层模型是其实现之一，不是唯一实现。
- 包管理器不实现具体鉴权策略；具体策略永远在服务端（消费者/宿主侧），客户端与包不可绕过。

### 10.2 智慧珞珈范围

- 只有涉及智慧珞珈数据/身份/委托 token 的包，在 manifest 声明对应宿主函数（如未来 `ailuo.luojia.*`）与权限需求 → AI珞 宿主按 `鉴权与委托授权设计.md` 三层模型强制执行。
- **其他包完全独立**：工具类、公开数据、纯计算包不声明任何鉴权需求，可在任何宿主/独立环境运行；智慧珞珈的接口、SSO、委托 token 对它们不存在。
- 边界：声明 `ailuo.luojia.*` 宿主函数的包只能运行在提供该能力面的 AI珞 宿主；未声明的包与宿主无关。
- 数据接入模式 A（机构授权）/模式 B（用户委托）只作用于智慧珞珈数据包，不扩散到整个包生态。

## 十一、bus 包化（第一个验收）

### 11.1 现状

`campus` 是内置 hosted 包：go:embed wasm、宿主函数 `ailuo.bus.query`、`bus.Store` 端口、demo 播种；`Record()` 已作为安装清单单一来源。

### 11.2 目标形态（两步）

**步骤 1：契约统一（不改变内嵌形态）**

- manifest 增加 `storage`（`campus/bus`、schema_version）与 `host_functions`（`ailuo.bus.query`）声明；
- 宿主函数注册表 + 按包投影校验接入 campus（内置/安装同路径）；
- 依赖约束化：`ToolDependencies` 升级为带版本约束。

**步骤 2：真正安装（安装目录包）**

- `campus.bus` 工件 + manifest + lock 由工具链生成并放入 `AILUO_RUNTIME_INSTALL_ROOT`；
- 内核启动发现、校验、注册、装载与任何安装包一致（现有路径已支持）；
- demo 数据作为**开发环境种子**（非权威、显式标记、生产禁启用）；生产数据仍经授权 ingestion 写入统一存储；
- 卸载/升级不丢存储数据（存储归宿主，包只声明不持有）。

### 11.3 边界

- guest 业务逻辑与现有 `internal/tools/bus` 一致，不反向依赖内核；
- 数据新鲜度/权威性治理在 guest（沿用 `contracts.ErrData*` 稳定错误）；
- 校车、校历等后续校园包复用同一包化路径，各自独立安装/升级。

## 十二、权限、治理与可观测性

- **安装 ≠ 授权**：包注册进宿主 Registry 不等于任何 App 可用；App 显式启用并收窄 permissions（鉴权设计六，不改）。
- **控制面/CI 专属**：安装、升级、卸载、发布属于受信控制面（9178 loopback admin + 运维 CLI + 发布 CI），普通用户与 Agent 不可触发；操作全审计。
- **签名预留**：当前保持 SHA-256 锁定；manifest 预留 `signature` 字段，密钥分发方案落地后启用（先哈希后签名，不破坏既有安装目录）。
- **可观测性**：沿用现有 Loader metrics（load/stop/调用数/耗时）；补包版本、升级事件、拒绝投影等低基数标签；包正文、参数、结果不进普通日志（现有净化规则）。

## 十三、包管理工具链

| 工具 | 职责 | 现状 |
|---|---|---|
| 构建器 | wasm 交叉编译（`build.sh`/`build.ps1` 已有） | 已有 |
| **安装器** | 生成 manifest + lock、校验工件哈希、按目录安全规则写入安装目录 | **新增**：`ailuo install` |
| 验证器 | 宿主启动全量校验（catalog.Discover） | 已有 |
| **升级器** | candidate 验证 + 原子切换 + drain | **新增**：`ailuo upgrade <id> <version>` |
| 卸载器 | drain + 删除目录 + 审计 | **新增**：`ailuo uninstall <id>` |
| 查询器 | 列出已装包/版本/状态 | **新增**：`ailuo list` |
| **发布器** | 打包 + 推注册表 + provenance/签名 | **新增**：`ailuo publish`（对接 CI 规范） |

- CLI、CI workflow 与未来控制面 API 共享同一核心实现（安装/校验/升级/卸载/发布逻辑不复制）。
- 安装目录写入遵循现有安全规则（绝对路径、属主校验、无符号链接、组/其他不可写）；非 Unix 平台保持 fail closed（既有 P1）。

## 十四、实施路线

1. **阶段 1（契约与投影）**：manifest 中性化（核心 + 宿主扩展段）；宿主函数注册表与按包投影校验；内置/安装包统一校验路径；bus 包化步骤 1。
2. **阶段 2（版本与生命周期）**：semver 约束解析器与 lock 生成；升级/降级流程（原子切换 + drain）；major 升级的宿主确认与存储迁移挂钩；`ailuo` CLI 基础（install/upgrade/uninstall/list）。
3. **阶段 3（发布与 CI）**：CI workflow 规范与可复用发布流水线；`ailuo publish`；注册表协议 v1（REST）；签名。
4. **阶段 4（生态）**：per-language SDK（rust/python 首批）；更多通用宿主函数能力面；注册表服务与外部宿主接入。

多语言 SDK 与 CI 规范可提前与阶段 2 并行，取决于外部采用需求；阶段 1-2 优先服务 AI珞 自身（bus 包化验收）。

## 十五、验收清单

- 无状态：实例重启/升级/崩溃恢复后权威状态一致；包内建库、持凭据、留用户状态被 Verify/审计拒绝。
- 版本：semver 约束解析正确；lock 固定可复现；冲突 fail closed；升级原子切换；降级不回滚数据。
- 投影：包声明外调用宿主函数被拒绝；内置/安装包同校验路径。
- 多语言：同一包格式由 wasm（hosted）与 gRPC（isolated）两种语言通路装载；SDK 与 CLI 契约一致。
- CI：包作者仓库接入可复用流水线后可完成构建→测试→版本→发布；不可变版本；发布审计。
- 鉴权独立性：智慧珞珈数据包声明 `ailuo.luojia.*` 依赖并经宿主鉴权；无鉴权声明的包独立运行。
- bus 包化：`campus.bus` 可安装/升级/卸载；卸载不丢存储数据；demo 种子生产禁启用。
- 治理：安装 ≠ 授权；升级不扩权；控制面/CI 操作全审计；签名预留不破坏既有目录。
- 门禁：新增功能覆盖对应 Go/Python 测试，跑完整门禁（AGENTS.md Validation）。
