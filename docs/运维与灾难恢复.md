# 运维与灾难恢复

## 1. 支持范围

当前可验证的生产部署轮廓是单个 Deployment 内的 Go 内核、一个通过 `executor.v1` 接入的 loopback Executor 包和一个 Go 管理的 SQLite 数据库。该轮廓适合单节点、单写者部署；它不声称提供多节点高可用。若容量、恢复时间或可用性要求超出本文件的基线，必须先实现另一种 Go 管理的数据库适配器，不能通过共享 SQLite 文件或绕过 Storage Port 扩展。

生产上线前，接受所有者必须根据实际业务确认 RPO、RTO、保留期、备份存储介质和责任人。本仓库给出的最低默认值是：每 6 小时一份完整备份（RPO 不超过 6 小时）、故障后 2 小时内完成恢复（RTO 不超过 2 小时）、保留最近 14 天备份、每月执行一次隔离恢复演练。更严格的机构要求只能收紧这些值。

## 2. 密钥与传输

Executor 所需的 Provider 密钥和配置由 Executor 包自己的 Deployment/监督器管理；Core 不读取、翻译或注入包的 Provider 环境变量。包若需要秘密，必须通过自己的批准秘密源和最小权限文件校验处理，秘密内容不得进入包清单、lock、普通日志或公共响应。

轮换步骤：

1. 在 Provider 侧创建新密钥，旧密钥暂不撤销。
2. 按 Executor 包的部署手册在其批准秘密源中原子轮换密钥，并重启/重载该 Executor。
3. 确认 `/readyz` 已通过 Executor 健康检查，且 9178 显示内核正在运行。
4. 在 Provider 侧撤销旧密钥，观察 `provider_unavailable`、`provider_rejected` 和就绪状态。
5. 不得把新旧密钥写入工单、命令历史、普通配置或日志。

Go/Python 与扩展 Runtime Host 的同 Deployment 边界只允许 loopback 或绝对 Unix 地址使用不安全 gRPC。Go 的启动与拨号路径、Python 的监听路径都会拒绝非本机明文地址。Runtime Host 还要求精确协议/运行时身份回显、512 KiB gRPC 上限和更小的 Invoke 字段上限。当前版本没有远程 TLS 配置；跨主机部署属于不支持状态，必须先增加双向认证、证书轮换、身份授权和降级失败测试。

isolated 扩展必须从安装解析器返回的绝对、非符号链接、不可被非受信主体写入的可执行文件启动；工作目录同样必须通过统一安全路径策略，Unix Socket 只能放在该目录内。Unix 校验当前 UID 与组/其他不可写，Windows 校验当前进程 token owner SID 和 DACL，非受信主体的写入、删除或 ACL 修改权限会被拒绝。发布、恢复、卸载和启动前都要复验。进程不继承内核环境，也不得通过环境注入凭据。关闭时先调用 Runtime Host Stop，再按配置宽限期终止整个进程组并清理绑定 Socket。hosted 当前实现了连接复用、runtime 数量和并发 Invoke 上限，但共享 Host 进程的 CPU、内存与文件系统隔离尚未形成部署合同，因此在该合同完成前只能承载经评审的低风险扩展。

扩展恢复默认关闭。设置 `AILUO_RUNTIME_INSTALL_ROOT` 后，值必须是规范化绝对路径；根目录、每个以 runtime ID 命名的子目录、`manifest.json`、`lock.json` 和实现文件都必须通过统一安全树校验，不得是符号链接，也不得向非受信主体开放写入、删除或 ACL 修改权限。目录格式版本为 `ailuo.package.v3`，isolated 组件必须在作者清单中显式声明进程模板，lock 必须同时固定清单原始字节和文件/目录工件的 SHA-256。只有 `hosted` 与 `isolated` 安装单元可从磁盘恢复；磁盘安装不得注入 `embedded` 实现。Unix 使用 UID/权限位，Windows 使用当前进程 token owner SID/DACL，其他平台会关闭失败。

若目录包含**未声明宿主函数**的 hosted 单元，还必须把 `AILUO_RUNTIME_HOST_ADDRESS` 设置为绝对 Unix Socket 或 loopback 地址，并在启动内核前由 Deployment 启动、监管相匹配的 Host Backend。声明了宿主函数的 hosted 单元由内核进程内的 wazero 沙箱装载（宿主函数是内核特权，不出进程），不需要该变量，也不需要外部 Host Backend。内核会整批验证并注册所有安装单元，只预热 `pin` 项；清单冲突、摘要变化、进程规格变化、Host 不可达或预热失败都会中止启动。非 pin 项在首次调用时加载。安装本身不会修改 App 配置，运维必须通过带 generation 比较交换的持久配置流程显式启用所需 Capability。升级时应先在隔离环境验证完整目录，以同文件系统原子切换整个安装根引用后滚动重启；不得原地改写已被运行中内核发现的清单、lock 或实现文件。

## 3. 健康、关闭与告警

`/healthz` 只表示 Go 进程存活。`/readyz` 在服务停止接单、SQLite 不可访问、协议不兼容或已安装 Executor 无法在有界时间内完成真实就绪探测时返回 `503`。负载均衡器应以 `/readyz` 控制流量，以 `/healthz` 判断进程是否需要重启，不能混用。

收到 `SIGINT` 或 `SIGTERM` 后，服务先停止接收新 Echo，再有界关闭 HTTP，持久化取消排队工作并取消活动 Run，等待后台 goroutine 退出，随后停止已加载 Runtime、关闭 Runtime Host，并按运行时策略停止由 Core 托管的 Executor 进程；共享关闭预算为 10 秒，兜底清理超时后强制终止并返回关闭错误。编排平台的 termination grace period 必须大于 15 秒。

`/metrics` 使用 Prometheus 文本格式，只包含闭集低基数标签。最低告警应覆盖：readiness 连续失败、5xx 比例、Run 失败/超时/取消、活动与排队 Run、首 Token 延迟、Capability/Tool/存储延迟、Provider 重试、Token 和成本增速。指标不包含 `app_id`、`echo_id`、`run_id`、`call_id` 或正文；按单任务排障使用同一 `trace_id` 的结构化 Span 日志。

## 4. 创建备份

备份命令要求源和目标均为绝对路径，目标必须不存在：

```bash
go run . backup \
  --database /srv/ailuo/ailuo.db \
  --destination /srv/ailuo-backups/ailuo-20260726T120000Z.db
```

命令不执行数据库迁移。它使用 SQLite `VACUUM INTO` 生成一致快照，将临时文件限制为 `0600`，执行 `integrity_check`、`foreign_key_check`、必需表/Run/App 配置/Capability 审计字段探测和连续迁移历史检查，`fsync` 文件后用同目录硬链接以“不存在才创建”语义原子发布，再同步目录。当前恢复合同接受连续迁移 1–27；旧版本会在正常启动时按前向链升级到当前迁移 27，测试覆盖历史版本升级和当前 Executor 中性 Schema。更老备份必须先由对应历史版本按版本链升级并重新备份，不能跳过兼容性验证。App 配置历史修订、Run 因果字段、接受时 scope 和按 Run 审计必须整体备份和恢复，不得只保留当前 head。该路径不会因检查与发布之间的竞争覆盖已有文件。运行中备份会占用当前单连接数据库，调度器应设置 10 分钟外部超时并避开高峰。取消或校验失败不会发布目标文件。

每次版本升级、迁移和校巴权威快照大规模导入前必须额外备份。备份完成后复制到具备服务端加密、不可变保留和独立访问控制的存储；本地副本不算灾难恢复副本。复制工具的凭据不由本服务持有。

## 5. 校验与恢复

定期校验：

```bash
go run . validate-backup \
  --backup /srv/ailuo-backups/ailuo-20260726T120000Z.db
```

恢复必须在隔离目录或已停止服务的节点进行。恢复命令永不覆盖现有目标：

```bash
go run . restore \
  --backup /srv/ailuo-backups/ailuo-20260726T120000Z.db \
  --destination /srv/ailuo-restored/ailuo.db
```

恢复流程：

1. 停止流量并确认原进程、Executor 子进程和所有数据库使用者均已退出。
2. 保留故障数据库及其 `-wal`、`-shm` 文件供取证，不在原路径直接恢复。
3. 校验候选备份；将其恢复到新的空路径。
4. 使用当前二进制启动一次迁移和 readiness 检查；迁移只前进，不修改既有迁移。
5. 核对 Echo/Run 状态与通用因果引用、事件最大序号、Run 接受时 scope、Run 引用的 App 配置历史修订、当前 App 配置 generation、当前校巴修订、权威性、完整性和有效期。
6. 执行最小只读冒烟调用，确认 Provider、Capability 和 SSE 链路。
7. 原子切换服务配置到新数据库路径并恢复流量。
8. 记录实际 RPO/RTO、选用备份、迁移版本和验证证据。

## 6. 保留、容量与损坏响应

备份保留默认采用最近 14 天加每月最后一份保留 12 个月；删除只由备份存储的生命周期策略执行，服务本身不扫描或删除备份目录。Echo、Run、事件、审计、幂等记录和 App 配置历史修订目前不自动清理：在没有 App 范围的法律保留、删除授权、审计访问控制、Run 引用分析和幂等安全证明前，自动删除会破坏恢复、配置重放与去重契约。容量告警应在数据库文件或所在卷达到 70% 和 85% 时触发，85% 后停止非必要导入并扩容。

出现 `SQLITE_CORRUPT`、完整性检查失败、磁盘 I/O 错误或异常迁移时：

1. 立即从 readiness 摘除实例并停止写入。
2. 保存数据库、WAL、SHM、二进制版本和脱敏日志；不得在原文件上运行修复命令。
3. 在隔离副本上确认最近一个通过校验的备份。
4. 按第 5 节恢复到新路径；损坏文件仅用于取证。
5. 确认根因（介质、断电、容量、并发访问、迁移或人为操作）后再恢复正常备份轮换。

## 7. 演练与发布门禁

每月恢复演练必须从异地备份开始，恢复到临时空目录，使用当前发布候选完成迁移、完整性检查和只读链路验证。每次数据库迁移变更还必须测试从上一迁移版本升级、升级前备份、恢复后再升级，以及取消/损坏/目标已存在等失败路径。没有最新演练证据时，不得把平台描述为具备已验证的灾难恢复能力。
