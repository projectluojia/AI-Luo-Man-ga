# AI珞 V3 重构说明

> 本文曾描述过期的多层能力模型。重构后以 `Package → Component → Capability`
> 为唯一公共包模型；当前目标与实现状态以 `docs/目标架构.md` 为准。

## 已确定的结构

- Package 管理分发、版本、来源、依赖和 lock。
- Component 管理运行模式、工件、进程监督、宿主函数声明和运行协议角色。
- Capability 是唯一对外入口，所有调用经过一个 Registry 和一个 Dispatcher。
- 非认知运行时使用 Provider Runtime；认知运行时使用 Executor Runtime。
- Core 统一持有权限、状态、存储、审计、取消、预算和 child Run。
- 包之间的构建期依赖由 Package manifest 显式声明；运行期组合只经 Core 的
  Capability Dispatcher，不允许组件扫描安装目录或通过私有地址形成隐式依赖。

## 不再保留

- 不再有独立的原子能力包/业务装配包分类。
- 不再有多套调用目标、Registry、Dispatcher 或授权路径。
- 不再通过兼容别名、旧字段解析或静默 fallback 支持历史清单。

内部代码仍可使用普通的领域对象、函数、库和 application service；这些名字不构成
Package 模型，也不能成为 Agent 可见的调用目标。

## 多 Agent

所有 Executor 实现同一 `executor.v1` 协议。Core 把本 Run 允许的 Capability 投影给
Executor；root 通过 Core 的 `run.create_child` 创建持久 child Run，child 只能获得父
Run 与当前 App 权限的交集，不能继续创建子 Run。Executor 不实现第二套多 Agent 逻辑。

## 验收顺序

1. 公共 manifest/lock 和 Protobuf 契约完成破坏性升版。
2. Loader、Registry、Dispatcher、确认和存储迁移使用同一 Capability 标识。
3. 安装、发现、升级、回滚、权限收窄、取消和恢复测试通过。
4. OpenAPI、README、运行手册和场景文档与当前代码一致。
