# AI珞 V3 系统架构说明

> 状态：实现基线。目标模型见 `docs/目标架构.md`；本文件只描述当前代码已经具备的
> 结构和边界，不把路线图当成实现证据。

## 一、运行总览

```text
Web / QQ / Ingress
        ↓
Go Core：身份、App 策略、Session、Echo/Run、队列
        ↓
Executor Runtime：一次受治理的认知执行
        ↓ CapabilityCall
一个 Dispatcher：Schema、权限、深度、幂等、确认、审计
        ↓
Provider Component：WASM 或独立进程
        ↓
Go 托管 Storage / 外部适配器
        ↓
持久事件与平台响应
```

Go Core 是唯一事实来源。Executor、Provider 和 Access 都不能直接拥有 Core 授权、
系统状态、业务数据库凭据或用户侧通道。

## 二、公共对象

| 对象 | 作用 |
| --- | --- |
| Deployment | 物理部署和最高安全隔离边界 |
| App | 数据、权限、会话和执行配置边界 |
| Package | 分发、版本、依赖、安装和升级单位 |
| Component | Package 内的运行单元；拥有 mode、工件和 role |
| Capability | 唯一公开调用契约；拥有 Schema、副作用、权限、确认和版本（当前跟随 Package） |
| Run | Go 持久化的执行记录；child Run 由 Core 创建 |

`Package` 使用 `manifest.json` 与 `lock.json`。清单格式当前为
`ailuo.package.v3`，组件 role 只有 `provider` 和 `executor`，mode 只有 `hosted` 和
`isolated`。Capability 规格在清单中直接声明，组件通过 `exports` 绑定其对外能力；
同一能力必须恰好由一个组件导出。

## 三、依赖与调用

Package 依赖负责来源、版本求解、安装顺序和完整性锁定，必须形成 DAG。运行期能力消费
由 Core 在任务图或 Executor 会话中通过 Dispatcher 完成；组件不保存其他组件的私有地址。
安装依赖和运行期调用不能混为一个字段，因为前者决定“能否安装”，后者决定“能否在本次请求执行”。

纯代码复用留在语言包管理器；需要独立权限、数据或生命周期的实现才进入 Ailuo Package
并成为 Provider Component。Core 内部的 identity、session、confirmation 等是普通领域
实现，不是可安装的公共调用目标。

## 四、两个最小运行协议

Provider Runtime 使用 `runtime_host.proto` 的 unary 生命周期与调用协议，当前协议版本
为 `3.0`，调用只携带受治理上下文和 `capability_id`。协议不再承载其他目标类别。

Executor Runtime 使用 `executor.proto` 的双向流协议，当前执行协议版本为 `3.0`。Core
下发 Run 输入和 Capability 投影，Executor 返回 CapabilityCall、结果、回复片段、用量、
取消响应和终态。任意 Executor 均可使用相同的 `run.create_child` Capability；只有
root Run 可以创建直接 child，child 不能继续派生。

两种协议共享版本化身份、deadline、取消、严格字段/消息大小校验和稳定错误分类，
不把两种不同状态机塞进一个万能协议。

## 五、权限、状态与数据

- 安装不等于授权；App Capability allowlist 默认保持关闭，启用来自受信控制面。
- 所有 Capability 调用都经过 Registry 与 Dispatcher，权限只能收窄，内部调用不能提权。
- write/external 调用需要幂等键；无法确认外部结果时不自动重做。
- Echo、Run、Task、Confirmation 使用持久状态机，非法转换、重复终态和错误 App 范围均拒绝。
- SQLite 是当前 Go Adapter，Schema 迁移只前向追加，当前版本为 27；备份验证按历史迁移
  版本检查结构，不能把历史迁移改写成新结构。
- Storage、事件、审计按 `app_id` 隔离，包 Storage 进一步绑定 `package_id` 和归属
  namespace；普通日志不记录正文、凭据、提示词或原始上游响应。

## 六、当前实现边界

已具备：Capability Registry/Dispatcher、Package/Component Loader、WASM/Process/GRPC
宿主、Python Executor、持久 Echo/Run/child Run、App 权限、幂等、确认、审计、SSE 和
包存储端口。

仍需在合并前以命令证据确认：Protobuf 漂移检查、完整跨模块门禁、安装后 Executor e2e、
签名信任链和真实学校数据授权。设计文档不替代这些验证。
