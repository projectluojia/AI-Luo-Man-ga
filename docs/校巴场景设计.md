# V3 校巴场景设计

> 状态：首个 Provider Package 的实施基线。校巴只验证通用 Package、Component、
> Capability 和 Core 治理，不在 Core 中保留业务特例。

## 一、范围

首期提供：线路/方向查询、站点查询，以及按站点与时间查询班次和直达行程。
实时位置、到站预测和主动提醒只有在获得权威字段及正式授权后单独评审。

权威数据来自智慧珞珈。数据先由受信数据管线写入 Go 托管的统一存储，再由 `campus`
Provider Package 通过 `ailuo.store` 读取。Provider 不持有数据库凭据，不访问外部平台。

## 二、Package 契约

| 对象 | 标识 |
|---|---|
| App | `campus-services` |
| Package | `campus` |
| Component | `campus.bus` |
| Capability | `campus.bus.stops.search`、`campus.bus.routes.list`、`campus.bus.journeys.search` |
| Storage namespace | `campus/bus` |

`packages/campus-bus/ailuo.toml` 直接声明 Component、Capability Schema、副作用和
`ailuo.store` 宿主函数。没有额外的中间能力分类；模型、HTTP SDK 和其他调用方只看
Capability；`campus.bus.journeys.search` 同时承担班次筛选和直达行程查询，不再拆出重复能力。

## 三、调用链

```text
Access
  → App allowlist
  → Registry / Dispatcher
  → campus Provider Component
  → ailuo.store
  → Go 托管存储
  → 结构化结果 / SSE
```

每次调用都经过 App 隔离、权限收窄、严格 Schema、deadline、幂等/确认规则（按副作用）
和审计。Provider 返回的结果不能改变 Core 的权限或系统状态。

## 四、数据治理

每个快照包含 source revision、来源、导入时间、有效截止时间、完整性和权威性。缺少、
不完整、非权威或过期快照时，Capability 返回稳定治理错误，不返回业务行，也不让
Executor 推测或补造事实。所有文档及引用使用稳定 ID；时间使用明确时区。

## 五、多 Agent

任意 Executor 都通过 `proto/executor.proto` 中的 Protobuf package/生成代码命名空间
`executor.v1` 接收 Go 投影的校巴 Capability；它不是协议版本。当前 Executor Runtime
协议版本为 `4.0`，运行时通过 `protocol_version` 协商并拒绝不匹配版本。root Run 可以
调用 Core 的 `run.create_child` 创建一个持久 child Run，并传递能力子集；Core 计算权限
交集、独立预算、父子关系、取消和结果路由。child 不能继续创建 child，Executor 不写
任何场景专用的多 Agent 逻辑。

## 六、测试与授权

测试使用 `testsupport/campus` 的现场编译 hosted 工件，不提交 WASM 构件和真实校方数据。
至少覆盖：Capability 注册、Schema/权限拒绝、App 隔离、空结果、排序、快照新鲜度、
并发调用、取消、child Run 和安装目录 `pack → install → list`。

真实学校数据接入前必须确认数据负责人、授权接口、更新频率、稳定 ID、保留/删除、凭据
轮换、测试数据隔离和故障联系人；当前代码不代表已经取得校方授权。
