# AI珞（爱珞）V3 仓库状态与路线图

本文件承载会频繁变化的实现状态、历史基线和工作顺序。长期工程约束只放在根目录 `AGENTS.md`。

## 状态口径

- 当前仓库已经实现可靠的校巴垂直链路，并证明 Go → Executor → Capability → Service → Tool → storage → SSE 路径；Python Executor 实现位于 `packages/agent`。
- 2026-07-26 审计 P0 清单已关闭，之后的地基模块也有持续测试证据；这不等于整个平台已经 production-ready。
- 文档中的“设计”不代表实现；只有代码、迁移、测试和部署验收同时存在时才可称“已实现并验证”。
- 真实校方身份、数据和部署边界仍需要独立授权与验收。

## 当前实现基线

### 内核与 Agent

- Go 管理 Echo/Run 持久状态机、固定 worker 调度、lease、恢复、取消、重试、App 容量与事件序号。
- Python 使用真实 OpenAI-compatible 原生 ToolCall；Go 执行精确 Capability 投影、Schema 复验、权限收窄、幂等、副作用治理和审计。
- Provider 具备 readiness、超时、取消、限流、并发限制、退避、Token/输出/成本预算和稳定公共错误。
- `packages/agent` 是与业务包同级的 `isolated` / `executor` 包；统一 Loader 管理安装目录中的 hosted、capability 和 executor 组件。
- `run.create_child` 异步创建一层持久 child Run，立即返回 `run_id/status`；`run.get_child_status` 查询直接 child。root 可并行创建多个直接 child，默认上限为 4（控制面可在 1–32 范围内调整）；child 不可继续创建 child，Echo 在整棵 Run 树结束后收敛。

### Service、Tool 与 Loader

- `campus` 是经包管理器安装的 hosted wasm32-wasi 包（源码位于 `packages/campus-bus`，安装目录装载）；Dispatcher → Loader → WasmHost → guest → host function → Go-managed storage 链路已实现。
- **通用包存储 `internal/kernel/packstore`**：`ailuo.store` 宿主函数（get/list/put/delete）+ 窄端口（SQLite/内存实现）；作用域强制为（App × 包 namespace），get/list 内嵌单事务一致的快照元数据（并发快照替换下 reader 永不观察跨修订混合），快照原子替换仅可信 Go 侧开放。**新增有状态包零内核改动**（声明 `[storage]` + 函数子集即可）。
- guest 领域模型与治理逻辑自包含在包仓库（只依赖标准库，2026-08-30 移除 `pkg/bus` 中立包）；数据新鲜度/权威性校验在 guest（读取响应内嵌元数据）。
- hosted Runtime 具备内存和执行时间预算、WASI 裁剪、调用隔离、严格 JSON 信封与稳定错误映射。
- isolated Runtime 在 Linux 使用资源限制，在 Windows 使用 Job Object；不支持的强安全语义 fail closed。
- 外部 `runtime-host` 已实现真实 Backend 与协议接线；声明内核 host function 的安装包仍只能由内核进程内的 WasmHost 执行。

### 包管理器（Package/Component 模型）

- **独立 contracts module**：`contracts/pkg/capability`、`contracts/pkg/packagecontract`、`contracts/pkg/packageio` 和 `contracts/pkg/projectcontract` 提供 Core 与外部包共同消费的稳定契约；其中 `projectcontract` 定义项目依赖清单与 `ailuo.lock` 校验；不依赖 Core `internal`。
- **独立 Package Manager module**：`package-manager/pkg/packagefmt`、`package-manager/pkg/packmgr`、`package-manager/pkg/projectmgr`、`package-manager/pkg/sdkgen` 与 `package-manager/cmd/ailuo-pm` 提供作者侧源清单、项目依赖闭包同步、构建、安装/升级/发布、SDK 生成和 CLI；Core 生产代码不导入包管理器实现。
- **Package = 分发/版本/升级单位，Component = 运行单元**（每组件一种 mode，`hosted`/`isolated` 命名暂不改）；组件间经统一 Capability 通信，依赖拓扑决定启动/停止顺序；双权限轴（Capability 逐调用 authZ + 组件沙箱权利）。
- **Loader 组编排**：Catalog 按组件产出内核记录（Capability 按组件 exports 映射到组件运行时，Service/Tools 路由到 Provider 基座）；`Manager.RegisterPackage`/`UpgradePackage`——候选按依赖拓扑加载、全部健康后组级原子切换、旧版本在途全部排空后反序停止（消费者先停、Provider 后停）、任一候选失败不切换。
- **CLI**：`ailuo-pm sync`（项目 `ailuo.toml` → 完整依赖闭包 → `ailuo.lock`）、`install`（作者源目录 / tarball / GitHub Release `owner/repo[@约束]`）、`upgrade`、`uninstall`、`list`、`pack`、`publish`（GitHub Releases 分发后端，纯 REST 免 git CLI，版本不可变）。
- **发布流水线**：可复用 `.github/workflows/package-publish.yml`（构建 → 必填测试 → tag 与 manifest.version 一致性 → pack → tarball 安装冒烟 → 上传 artifact → tag 时 publish → 注册表安装闭环验证）；调用方必须提供 `test-command`，需要构建工件时还必须提供匹配包语言的 `build-command`，只有已提交完整工件时才能留空；workflow 输出 artifact ID，发布 job 不执行调用方构建命令；当前仓库未配置 tag caller，包管理器库测试覆盖打包与安装路径。

### Access、身份与上下文

- Web、统一 ingress 和 QQ OneBot v11 适配器均通过标准 `internal/access.Hub` 接入，不直接创建 Echo 或写业务表。
- Deployment User、外部身份、AppMembership、禁用状态和版本化绑定已经持久化并按 App 隔离；不存在匿名降级。
- direct/group/system Session、Message、BlobStore 沙箱、平台消息去重和受限历史读取已经实现。
- QQ 支持群/私聊 allowlist、自动开通受限身份、群聊 @ 过滤、快速回复、戳一戳和不带 @ 的 child Run 生命周期通知。
- Go 的 context assembler 组合配置提示、渠道提示、当前消息、受限历史和 Capability 投影，并持久化确定性摘要与来源版本。

### 配置、提示词与治理

- App 配置使用不可变 revision + generation CAS，支持即时撤权、App disable、历史 Run 配置恢复与动态模型 readiness。
- 9178 loopback WebUI 统一配置 Go 主进程、模型、QQ Access、提示词与个性化目录；NapCat/LLBot 保持独立部署。
- L3 `prompt` Service 暴露 `prompt.preference.get/set/reset`，用户偏好按 `(app_id,user_id)` 持久化；基础人格与渠道规则已从 V2 迁移。
- Confirmation 五态状态机、参数摘要绑定、Dispatcher 校验和确认过期持久任务已经实现。
- 通用持久 Task 状态机支持类型注册、参数 Schema、lease、续期、恢复、有界重试和 App 容量。

### 存储与可观测性

- SQLite 统一存储使用连续前向迁移、App-scoped 复合键、严格约束、备份、完整性校验和无覆盖恢复。
- 当前 Schema 迁移为 1–25：23 提供用户提示词偏好，24 固化 child Run 任务正文，25 将包文档快照统一为通用存储；迁移均为前向追加，已应用迁移不改写。
- 校巴快照导入具备来源、权威性、完整性、有效期、引用和原子激活治理；Core 不播种业务演示数据，测试夹具中的 Demo 快照不进入生产启动路径。
- Go/Python 使用统一中文结构化日志、W3C trace 传播、稳定低基数字段、Prometheus 指标和集中净化。
- 公共 HTTP/SSE/Agent 错误不返回原始内部原因；提示词、消息、Tool 参数和敏感正文不进入普通日志。

## 生产阻塞项

### P0

当前没有已知未关闭 P0。新的安全、数据完整性、部署边界或可靠性问题按影响重新定级，历史通过不构成永久豁免。

### P1


- 当目标部署规模、并发或高可用要求超出 SQLite 时，需要新的 Go-managed production database adapter。
- 需要取得书面授权并实现智慧珞珈官方数据 ingestion adapter。
- 多入口产品化仍需真实前端、部署认证、运维指标告警和环境级验收。
- 包管理器：更多语言 SDK（WIT 路线可选演进）、自托管注册表、签名信任链、Loader 公共模块抽取与包管理器独立 repo（当前 projectmgr/packmgr/sdkgen 已可复用）。

## 推荐工作顺序

除非用户重新排序：

1. 处理新发现的 P0。
2. 完成部署环境与 hosted package 剩余边界。
3. 完成授权的真实数据 ingestion。
4. 完成真实产品入口、认证与运维验收。
5. 在稳定地基上增加产品 Capability。
6. 包管理器生态：契约形式化 + 多语言生成器 → 自托管注册表 → 外部包作者接入。

不要在没有用户重新分配的情况下实现由他人负责的 Tool/package-management 对比方案。

## 不变的垂直链路

```text
Access request context
  -> App Capability policy
  -> Registry / Dispatcher
  -> Service
  -> reusable Tool
  -> Go-managed storage port
  -> structured result and persisted events
```

Web、QQ、其他 Access、Python Executor、未来数据库适配器和授权 ingestion 都附着在这条链路上，不移动所有权边界。
