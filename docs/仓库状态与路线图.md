# AI珞 V3 仓库状态与路线图

> 更新时间：2026-09-04
>
> 本文件区分当前代码、验证证据和剩余阻塞项。设计文档不能替代测试或 CI 结果。

## 当前基线

- Go Core 是唯一系统核心，负责 Access、App、Identity、Session、Echo/Run、调度、
  Loader、Capability Registry/Dispatcher、Storage、Confirmation、审计和恢复。
- 公共包模型已经切换为 `Package → Component → Capability`；manifest/lock 使用
  `ailuo.package.v3`。
- Component role 只有 `provider` 与 `executor`，mode 只有 `hosted` 与 `isolated`。
- 所有 Capability 走同一个 Registry 和 Dispatcher；没有第二条调用或授权路径。
- Provider Runtime 使用 unary `runtime_host.proto` 3.0；Executor Runtime 使用双向流
  `executor.proto` 3.0。两者共享身份、生命周期、治理上下文、大小限制和稳定错误。
- Executor 只能消费 Core 投影的 Capability。多 Agent 是 Core 创建的持久 child Run，
  不是 Executor 进程内的私有任务。
- SQLite 当前迁移版本为 27；安装、lock、包文档、App/Run、幂等、确认、事件和审计均
  有明确持久化边界，包文档按 `app_id + package-qualified namespace` 隔离。
- `packages/campus-bus` 是真实 Provider Package；`packages/agent` 是 Executor Package；
  Core 不硬编码两者的业务实现。

## 本次重构已完成

- 删除旧的多层能力规格、工具注册、业务装配注册和双路 Dispatcher。
- Capability 直接进入 Package 清单并按 Component `exports` 绑定。
- Package Manager、Catalog、Loader、WASM/GRPC Host、Access、Executor 和测试夹具统一
  使用 Capability 标识。
- Runtime Host 删除其他目标类别字段；Executor 预算改为 Capability 调用数。
- Prompt 的 L3 实现迁移为 `internal/providers/prompt`，当前仍是 Core-owned Provider；
  Core 内部的 identity/session/confirmation application service 仍是普通领域实现，不是 Package 类型。
- App 初次创建不再把安装包能力自动加入 allowlist；授权必须由受信控制面显式完成。
- Package sync 已采用 lock 优先、显式 `--update`、候选安装根整体切换和事务恢复；
  不会因为单个项目同步而删除共享安装根中的其他已校验包。
- Package Manager 的安装根变更已加入进程内互斥与跨进程独占锁；崩溃遗留锁只允许
  用户确认后通过 `unlock --force` 清理，不按 PID 自动删除未知锁。
- Loader 注册与包组发布增加批量校验/补偿路径；Runtime Lease 使用生成号识别实例，
  不比较可能不可比较的 Runtime 接口值。

## 后续路线

- 先完成本次破坏性契约迁移和全量门禁，不添加兼容层。
- 再实现 Provider/Executor 的签名信任链；当前以一个 Deployment 一个活动 Executor
  为明确约束，未来出现多 Executor 需求时再引入 App 级选择。
- 有真实第二个 Executor 或跨团队嵌入需求时，再扩展协议版本；不预先合并两个不同
  状态机为万能协议。
- 有真实学校授权后实现数据源 Provider 与 Core 持久任务图；能力和数据治理继续由
  同一 Capability/Dispatcher/Storage 边界承载。
