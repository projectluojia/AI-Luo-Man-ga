# AI珞（爱珞）V3 仓库状态与路线图

本文件承载会频繁变化的实现状态、历史基线和工作顺序。长期工程约束只放在根目录 `AGENTS.md`。

## 状态口径

- 当前仓库已经实现可靠的校巴垂直链路，并证明 Go → Python Executor → Capability → Service → Tool → storage → SSE 路径。
- 2026-07-26 审计 P0 清单已关闭，之后的地基模块也有持续测试证据；这不等于整个平台已经 production-ready。
- 文档中的“设计”不代表实现；只有代码、迁移、测试和部署验收同时存在时才可称“已实现并验证”。
- 真实校方身份、数据和部署边界仍需要独立授权与验收。

## 当前实现基线

### 内核与 Agent

- Go 管理 Echo/Run 持久状态机、固定 worker 调度、lease、恢复、取消、重试、App 容量与事件序号。
- Python 使用真实 OpenAI-compatible 原生 ToolCall；Go 执行精确 Capability 投影、Schema 复验、权限收窄、幂等、副作用治理和审计。
- Provider 具备 readiness、超时、取消、限流、并发限制、退避、Token/输出/成本预算和稳定公共错误。
- `agent` 是与业务 Service 同级的 isolated Runtime；统一 Loader 管理 campus hosted Runtime、agent Runtime 与 installed packages。
- `agent.run` 异步创建一层持久 child Run，立即返回 `run_id/status`；`agent.status` 查询直接 child。root 可并行创建多个直接 child，默认上限为 4（控制面可在 1–32 范围内调整）；child 不可继续创建 child，Echo 在整棵 Run 树结束后收敛。

### Service、Tool 与 Loader

- `campus` 是 hosted wasm32-wasi 内置包；Dispatcher → Loader → WasmHost → guest → host function → Go-managed storage 链路已实现。
- `internal/tools/bus` 提供跨 Service 可复用的 stops/routes/journeys 原子 Tool；Service 通过 `ToolDependencies` 声明依赖。
- hosted Runtime 具备内存和执行时间预算、WASI 裁剪、调用隔离、严格 JSON 信封与稳定错误映射。
- isolated Runtime 在 Linux 使用资源限制，在 Windows 使用 Job Object；不支持的强安全语义 fail closed。
- 外部 `runtime-host` 已实现真实 Backend 与协议接线；需要内核 host function 的内置包仍只能在内核进程执行。

### Access、身份与上下文

- Web、统一 ingress 和 QQ OneBot v11 适配器均通过标准 `internal/access.Hub` 接入，不直接创建 Echo 或写业务表。
- Deployment User、外部身份、AppMembership、禁用状态和版本化绑定已经持久化并按 App 隔离；不存在匿名降级。
- direct/group/system Session、Message、BlobStore 沙箱、平台消息去重和受限历史读取已经实现。
- QQ 支持群/私聊 allowlist、自动开通受限身份、群聊 @ 过滤、快速回复、戳一戳和不带 @ 的 child Run 生命周期通知。
- Go 的 context assembler 组合配置提示、渠道提示、当前消息、受限历史和 Capability 投影，并持久化确定性摘要与来源版本。

### 配置、提示词与治理

- App 配置使用不可变 revision + generation CAS，支持即时撤权、App disable、历史 Run 配置恢复与动态模型 readiness。
- 9178 loopback WebUI 统一配置 Go 主进程、模型、QQ Access、提示词与个性化目录；NapCat/LLBot 保持独立部署。
- L3 `prompt` Service 暴露 `prompt.preference.get/set/reset`，用户偏好按 `(app_id,user_id)` 持久化；基础人格与渠道规则已从 V2 迁移。
- Confirmation 五态状态机、参数摘要绑定、Dispatcher 校验和确认过期持久任务已经实现。
- 通用持久 Task 状态机支持类型注册、参数 Schema、lease、续期、恢复、有界重试和 App 容量。

### 存储与可观测性

- SQLite 统一存储使用连续前向迁移、App-scoped 复合键、严格约束、备份、完整性校验和无覆盖恢复。
- 校巴快照导入具备来源、权威性、完整性、有效期、引用和原子激活治理；生产环境拒绝 Demo 数据。
- Go/Python 使用统一中文结构化日志、W3C trace 传播、稳定低基数字段、Prometheus 指标和集中净化。
- 公共 HTTP/SSE/Agent 错误不返回原始内部原因；提示词、消息、Tool 参数和敏感正文不进入普通日志。

## 生产阻塞项

### P0

当前没有已知未关闭 P0。新的安全、数据完整性、部署边界或可靠性问题按影响重新定级，历史通过不构成永久豁免。

### P1

- 非 Unix 平台的外部 hosted package 安装目录仍受无法等价验证文件属主的 fail-closed 限制。
- 当目标部署规模、并发或高可用要求超出 SQLite 时，需要新的 Go-managed production database adapter。
- 需要取得书面授权并实现智慧珞珈官方数据 ingestion adapter。
- 多入口产品化仍需真实前端、部署认证、运维指标告警和环境级验收。

## 推荐工作顺序

除非用户重新排序：

1. 处理新发现的 P0。
2. 完成部署环境与 hosted package 剩余边界。
3. 完成授权的真实数据 ingestion。
4. 完成真实产品入口、认证与运维验收。
5. 在稳定地基上增加产品 Capability。

不要在没有用户重新分配的情况下实现由他人负责的 Tool/package-management 对比方案。

## 不变的垂直链路

```text
Access request context
  -> App Capability policy
  -> Registry / Dispatcher
  -> Service
  -> reusable Tool
  -> Go-managed storage port
  -> structured result and persisted events
```

Web、QQ、其他 Access、Python Executor、未来数据库适配器和授权 ingestion 都附着在这条链路上，不移动所有权边界。
