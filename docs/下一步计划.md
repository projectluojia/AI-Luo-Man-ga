# V3 智能体项目下一步计划

| 优先级 | 任务 | 主要产出 |
|---|---|---|
| P0 | 选择一个低敏感、价值明确的校内场景作为首个 Demo，明确用户流程、功能边界和数据需求 | Demo 场景说明 |
| P0 | 打通“前端 → Echo ID → Golang Core → Executor Package → Capability → 结果返回”的完整链路 | 可运行 Demo、展示视频 |
| P0 | 固化唯一的 Package → Component → Capability 模型、统一包管理器、Loader、Dispatcher、数据库和 App 授权边界 | V3 架构规范 |
| P0 | 实现最大调用深度、调用图校验及非幂等循环拦截，并完成核心链路压测 | 测试与压测结果 |
| P0 | 梳理 Demo 所需数据及权限，通过校方正式渠道申请接口，Demo 阶段优先使用模拟或脱敏数据 | 数据需求与授权清单 |
| P1 | 深度体验智慧珞珈、一网通办等系统，整理无法闭环、重复操作和系统跳转等真实痛点 | 校内场景调研报告 |
| P1 | 对接校方可提供的算力、存储、测试环境和统一数据共享平台 | 资源对接清单 |
| P1 | Demo 通过评审后，选择限定用户开展小范围试点，根据反馈逐步扩大覆盖范围 | 试点方案及反馈记录 |

需要尽快确认：首个 Demo 场景、各任务负责人、演示时间、包发布与 CI 验收责任人，以及校方数据与资源对接人。
