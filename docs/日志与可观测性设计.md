# 日志与可观测性设计

## 1. 目标与边界

日志是 Go 内核统一治理的一部分，不是某个 Service、Tool 或 Agent 的私有附属功能。Go 代码统一使用 `internal/observe`，Python Agent 统一使用 `agent.observe`。两端采用相同的关联标识、字段语义和隐私边界，使一次 Web 请求能够跨越 Echo、Run、Python Agent、Capability、Service、Tool 与存储层被完整追踪。

日志以中文可读性为第一要务，同时保证机器可检索性：事件说明使用中文，稳定字段名使用英文。日志包属于内核基础设施，不注册成业务 Tool，也不会暴露给模型调用。

## 2. 输出格式

本地默认使用 `console`，输出中文级别、中文事件和紧凑结构化字段。生产环境建议使用 `json`，以便日志平台解析、索引和告警。JSON 的 `level` 使用标准英文值，`message` 仍使用中文。

每条日志自动携带：

| 字段 | 含义 |
| --- | --- |
| `time` | UTC 时间戳 |
| `level` | 日志级别 |
| `message` | 中文事件说明 |
| `service` | 进程或服务名称 |
| `environment` | 部署环境 |
| `pid` | Go 进程标识；Python 日志暂不输出 |
| `component` | 产生日志的逻辑组件 |

## 3. 关联标识

Web Access 接收 W3C `traceparent`；仅接受 version 00、32 位非零小写十六进制 trace ID、16 位非零 span ID 和合法 flags。没有 `traceparent` 时可兼容 32 位小写十六进制 `X-Trace-ID`，其他值一律丢弃并生成新 trace ID。响应返回 `X-Request-ID`、规范化的 `X-Trace-ID` 和新的 `traceparent`。创建 Echo 后，Web Access 在脱离 HTTP 生命周期前复制日志上下文，因此后台执行不会因请求结束而丢失关联信息。

调用链按适用范围携带以下字段：

| 字段 | 生命周期 |
| --- | --- |
| `request_id` | 一次外部请求或一次内核调用 |
| `trace_id` | 跨入口、进程和内部调用的完整链路 |
| `span_id` | 当前 HTTP 或 Run 工作单元 |
| `parent_span_id` | 上游 W3C 或跨进程父 Span |
| `app_id` | App 数据与权限边界 |
| `echo_id` | 一次用户任务 |
| `run_id` | 一次 Executor 执行尝试 |
| `parent_run_id` | 可选的通用因果父 Run；没有因果关联时不出现 |
| `call_id` | 一次 Executor CapabilityCall |
| `capability_id` | 当前 Run 获得投影的 Capability |
| `service_id`、`tool_id` | Go 内核内部路由目标 |

字段只在语义成立时出现，不使用空字符串伪造完整链路。HTTP 创建 server Span，Go Run 创建执行 Span，并在 `StartRun` Protobuf 中传递 `trace_id`、父 Span 与可选因果标识；Executor 校验后创建自己的 Span，但不记录任务或结果正文。内部调用创建新的 `request_id`，同时继承适用的 `trace_id`、`app_id`、`echo_id`、`run_id` 与 `parent_run_id`。

## 4. 日志级别

| 级别 | 使用场景 |
| --- | --- |
| `debug` | 请求开始、事件写入、模型回复片段长度、健康检查成功等高频诊断信息 |
| `info` | 服务启动、注册完成、Echo 创建、Run 开始与完成、Capability 成功等正常生命周期节点 |
| `warn` | 可预期的无效输入、未找到资源、取消、业务调用失败、非权威演示数据等需要关注但不代表进程故障的事件 |
| `error` | 持久化失败、协议违例、依赖不可用、未捕获异常、服务异常退出等必须处理的故障 |

同一层不重复记录没有新增信息的错误。跨边界记录时必须增加当前边界的标识、状态或耗时，使上下游日志具有独立诊断价值。

## 5. 详细度标准

重要边界至少记录以下信息中的适用项：

- 生命周期状态：开始、完成、取消、超时或失败。
- 稳定标识：App、Echo、Run、调用与路由目标标识。
- 工作规模：Capability 数量、消息数量、事件序号、结果字节数或文本字符数。
- 性能信息：`duration_ms`、超时配置与数据库受影响行数。
- 结果信息：状态码、成功标志、错误码、异常类型与是否可重试。

“足够细致”不等于记录业务正文。排查模型调用时记录模型名、消息数量、Tool 数量、结束原因、文本长度、ToolCall 数量、累计 Token/成本计数、重试次数和耗时；排查 Capability 时记录标识、参数字节数、结果字节数、成功状态和耗时。

## 6. 隐私与脱敏

以下内容禁止进入运行日志：

- API Key、密码、令牌、凭据、Cookie 与授权头；
- 用户输入、模型回复正文、系统提示词和模型消息列表；
- ToolCall 参数、Tool 返回值、HTTP 请求体与响应体；
- 未经筛选的上游异常响应、数据库原始载荷或其他敏感业务数据。

日志包会按字段名强制脱敏常见秘密、正文、`error` 与 `reason` 字段，超长字符串按 Unicode 字符安全截断。Go 的集中错误入口只记录稳定 `error_class` 和 Go 类型，不记录 `err.Error()`；Python 异常日志只记录异常类型和调用栈文件名/位置，不记录可能含上游响应正文的异常字符串。调用代码仍必须遵守最小披露原则：正文改记字符数，载荷改记字节数，无法安全描述的数据改记哈希或稳定标识。

Python 生产启动时关闭 OpenAI SDK、HTTPX、HTTP Core 和 gRPC 自带的明文日志，Provider 状态只通过 `agent.observe` 记录稳定错误码、可重试标志、次数、计数与耗时。不得临时恢复第三方日志来排障；需要的新诊断字段必须先进入集中脱敏和负面泄露测试。

Runtime Host 协议不接受远端自由文本错误，只接收稳定错误码和重试标志。Go 管理的 isolated 扩展进程不继承内核环境，且标准输出与标准错误默认丢弃，不能借第三方日志旁路披露参数、结果、路径或凭据。需要扩展诊断时，必须先设计进入集中观测接口的闭式字段和泄露负面测试，不能直接转发子进程输出。

App 的 `ExecutorConfig` 是受 Go 管理的 opaque 配置正文，保存在 App 配置修订表并通过执行者启动帧投影；Executor Deployment 自有的 Provider、模型和 secret configuration 不进入 Core 配置表，由执行者 Deployment 管理。配置创建、更新、读取、恢复和健康检查日志只允许记录 `app_id`、`config_revision`、`config_generation`、预算计数、状态和耗时，不得记录 ExecutorConfig、权限列表或完整 Capability 列表。

Capability 审计与运行日志相互独立。审计数据通过统一 JSON 清洗器处理，敏感键被替换，非法或超限载荷只保留字节数、原因和 SHA-256 摘要。审计数据还必须由存储层实施访问控制与保留期限。

Executor 的输入、上下文和结果正文属于受治理 Run 数据，只能进入 Go 管理的 Run/幂等业务状态，不进入普通日志、指标或公共 Run 元数据。Access 可通过 App-scoped SSE/Run API 查看允许公开的状态和结果，但不公开凭据、ExecutorConfig、Capability 参数或内部响应正文。

## 7. 指标与追踪输出

`GET /metrics` 输出 Prometheus 0.0.4 文本，覆盖 HTTP 请求/状态/耗时、活动与排队 Run、Run attempt 终态/耗时、Run 自动重试、首 Token 延迟、取消、Provider 重试、模型输入/输出 Token 与成本、Capability/Tool 成败和耗时、存储操作成败与耗时，以及 Loader 的加载/停止成败与耗时和活动运行时调用数。标签严格来自代码闭集，只使用状态类别和成功/失败，不接受 App、Echo、Run、调用或外部字符串作为标签。

Span 当前通过 JSON 结构化日志导出，包含 `trace_id`、`span_id`、可选 `parent_span_id`、`span_name`、状态和耗时。部署日志采集器必须保持这些字段，才能在 Go Web、Go Run、Python Agent 和内部调用之间重建分布式链路。当前未内置厂商专用 exporter；接入 OpenTelemetry Collector 时应在 `internal/observe` 统一实现，不能由 Service 或 Tool 私自上报。

## 8. 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AILUO_ENVIRONMENT` | `development` | 环境名称 |
| `AILUO_LOG_LEVEL` | `info` | `debug`、`info`、`warn`、`error` 或对应中文值 |
| `AILUO_LOG_FORMAT` | `console` | `console` 或 `json` |
| `AILUO_LOG_SOURCE` | `false` | 必须保持 `false`；启用会因泄露源码路径而拒绝启动 |
| `AILUO_LOG_MAX_VALUE_LENGTH` | `4096` | 单个字符串字段最大字符数 |

生产环境推荐使用 `json` 和 `info`。短时故障诊断可提升到 `debug`，恢复后应回到 `info`，避免高频事件长期增加存储与检索成本。

## 9. 验证要求

日志相关变更至少验证：

- 中文控制台级别与事件可读性；
- JSON 输出合法且字段稳定；
- 密钥、正文和 Tool 参数脱敏；
- Unicode 截断不会破坏字符；
- HTTP 关联标识写入上下文和响应头；
- 畸形 traceparent/trace ID 被拒绝，Go→Python 追踪字段经过双方校验；
- 指标名称与标签为低基数闭集且不含业务标识；
- 原始错误、Provider 正文、数据库路径和凭据不出现在 console/JSON 日志；
- 后台 Echo 继承请求关联上下文；
- 审计载荷在脱敏、非法和超限场景下始终保持合法 JSON。
